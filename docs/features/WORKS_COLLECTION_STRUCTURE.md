# 通用作品集与叙事章节

## 定位

作品集用于收纳创作成果，而不是只服务剧本或 IP 角色。一个作品可以是图片、歌曲、专辑、剧本、短剧、电影，也可以是既有的电视剧、小说、动画、游戏、漫画等。作品的类型用于描述媒介；作品的结构用于决定是否需要额外的内容管理能力。

## 三种作品结构

| 结构 | 适用场景 | 当前能力 |
| --- | --- | --- |
| `single`（单体作品） | 图片、单曲、独立短片等 | 维护作品元数据、图片库、封面、标签与人物设定 |
| `collection`（集合结构） | 专辑、系列作品等 | 维护集合元数据、图片库、封面、标签与人物设定；曲目/条目管理预留为下一阶段 |
| `narrative`（叙事结构） | 剧本、短剧、电视剧、小说等 | 在人物设定之外提供章节、正文、进度、人物出场和章节关联图片管理 |

新建作品时，界面会按作品类型推荐结构：剧本、短剧、电视剧、小说推荐叙事结构；专辑推荐集合结构；图片和歌曲等推荐单体作品。推荐只是一项初始值，用户可自行选择实际结构。

## 叙事章节

只有结构为 `narrative` 的作品会在详情页主区域显示章节；人物设定作为右侧辅助栏，避免挤占正文和章节的主要创作空间。

章节按手动顺序排列，每章包含：

- 标题、梗概和正文；
- 状态：大纲、草稿、审阅、定稿；
- 可选的目标字数；
- 本章登场人物及可选备注。
- 可从当前作品图片库中多选关联的概念图、分镜或剧照。

章节可以新建、编辑、软删除和上下调整顺序。章节的正文与字数统计在本地保存，不会改变原有作品简介；叙事作品的简介仍用于总纲、世界观或核心设定。

## 数据关系

```text
works (structure_mode = narrative)
 ├── characters
  ├── work_images
  └── work_chapters
        └── chapter_character_relations ──> characters
        └── chapter_image_relations ──────> work_images
```

- `work_chapters` 归属于一个作品，删除作品时由外键级联清理。
- `chapter_character_relations` 是章节和人物的多对多关系，可为每个角色保存该章的出场备注。
- `work_images` 是作品级可复用图片库；其中一张可被标记为封面，图片不因关联多个章节而重复存储。
- `chapter_image_relations` 是章节和作品图片的多对多关系；删除图片时会同步移除该图片在所有章节中的关联。
- 章节删除采用软删除；删除作品时，关联章节也会标记为删除，避免后续查询继续显示它们。

## 作品图片库

在作品详情左侧的“作品图片”区域可一次添加多张图片。上传时图片会转换为 WebP，并存入当前作品自己的 `images/` 目录。可以把任意一张图库图片设为封面；封面同样是一张图库图片，因此也可以被章节关联。

编辑章节时，在“本章关联图片”中多选作品图片即可。章节卡片会展示关联数量和缩略图，便于浏览时识别分镜、场景或视觉参考。

## 数据库迁移与兼容性

章节基础功能对应数据库 schema v4；作品图片库与章节图片关联对应 schema v7：

1. 为 `works` 新增 `structure_mode`，默认值为 `single`。
2. 新增 `work_chapters` 与 `chapter_character_relations`，并创建按作品顺序和人物关联查询的索引。
3. 已存在的作品保持 `single`，不会因为升级而突然显示章节 UI；需要章节时可在编辑作品时显式切换为 `narrative`。
4. 新增 `work_images` 与 `chapter_image_relations`，并创建按作品、封面和章节图片查询的索引。
5. 升级时，已有的 `cover_path` 会登记为该作品图片库中的封面记录，不复制或移动原文件。

新安装的数据库会直接创建完整表结构；旧数据库会依次执行迁移，包含 v6 → v7 的图片库迁移。

## 当前边界

- 本次完成了通用作品类型、结构选择和叙事章节管理。
- 专辑的曲目、系列作品的条目管理尚未实现；目前 `collection` 只用于正确表达集合类作品，后续可在此结构上增加曲目或子作品实体。
- 作品集仍可独立使用；角色关联是可选能力，不要求先创建 IP 资产。
